# Хеш-функция и её свойства

## Повторения в массиве (DUPLICATES)

Дан несортированный массив A из n натуральных чисел, нужно узнать, есть ли в нём два одинаковых элемента. Код всех четырёх вариантов лежит в `solution.py`.

1. Наивный алгоритм, O(n²). Перебираем все пары i < j и сравниваем A[i] и A[j]. Пар n(n-1)/2, отсюда квадрат. Дополнительная память O(1).
2. Через сортировку, O(n log n). Сортируем массив (например, слиянием или кучей), после чего одинаковые элементы стоят рядом. Один проход проверяет соседей: A[i] == A[i+1]. Сортировка занимает O(n log n), проход O(n).
3. Через хеш-таблицу, ожидаемое O(n). Идём по массиву и кладём элементы в хеш-множество. Если элемент уже есть в множестве, нашли повтор. Вставка и поиск в хеш-таблице при хорошей хеш-функции и ограниченном коэффициенте заполнения в среднем стоят O(1), значит всего ожидаемое O(n). В худшем случае (все ключи в одной цепочке) O(n²).
4. Если n <= k и все A[i] <= k, O(k). Заводим массив флагов seen размером k+1, изначально false. Для каждого x: если seen[x] уже true, повтор найден, иначе ставим seen[x] = true. Инициализация O(k), проход O(n) <= O(k). По сути это хеш-таблица с хеш-функцией h(x) = x без коллизий (прямая адресация).

## Открытая и закрытая адресация

Ключи A = [67, 13, 49, 24, 40, 33, 58], таблица размера 9, h(k) = (11k + 4) mod 9.

| k | 11k+4 | h(k) |
|---|---|---|
| 67 | 741 | 3 |
| 13 | 147 | 3 |
| 49 | 543 | 3 |
| 24 | 268 | 7 |
| 40 | 444 | 3 |
| 33 | 367 | 7 |
| 58 | 642 | 3 |

Закрытая адресация (метод цепочек): элементы с одинаковым адресом лежат в списке своей ячейки.

```
0: -
1: -
2: -
3: 67 -> 13 -> 49 -> 40 -> 58
4: -
5: -
6: -
7: 24 -> 33
8: -
```

Открытая адресация (линейное пробирование, шаг +1): всё лежит прямо в массиве, при занятой ячейке берём следующую.

```
67 -> 3
13 -> 3 занята -> 4
49 -> 3, 4 заняты -> 5
24 -> 7
40 -> 3, 4, 5 заняты -> 6
33 -> 7 занята -> 8
58 -> 3, 4, 5, 6, 7, 8 заняты -> 0 (по кругу)

[0] 58  [1] -  [2] -  [3] 67  [4] 13  [5] 49  [6] 40  [7] 24  [8] 33
```

Пять ключей из семи получили адрес 3, потому что функция плохо подходит для этих данных. При открытой адресации из-за этого образовался длинный кластер 3-8, и ключ 58 нашёл место только после шести проверок.
