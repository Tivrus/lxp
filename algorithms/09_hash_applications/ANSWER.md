# Применение хеш-функций на практике

Примеры 1-6 из таблицы написал в solution.py.

| Где | Какая функция | Зачем |
|---|---|---|
| 1. Контроль целостности файлов (контрольные суммы на страницах загрузки, `sha256sum`, проверка пакетов в apt и npm) | SHA-256 | изменение одного байта даёт совсем другой хеш, подмену или повреждение видно сразу |
| 2. Хранение паролей | bcrypt, scrypt, Argon2, PBKDF2 | в базе лежит не пароль, а медленный хеш с солью: при утечке пароли не прочитать, перебор дорогой |
| 3. Дедупликация (резервные копии, Dropbox, Docker-слои) | SHA-1 / SHA-256 от блока | одинаковые блоки хранятся один раз, ссылки идут по хешу |
| 4. Поиск подстроки (алгоритм Рабина-Карпа, антиплагиат) | полиномиальный "скользящий" хеш | хеш окна пересчитывается за O(1) при сдвиге, сравнение строк только при совпадении хешей |
| 5. Фильтр Блума (кеши, базы Cassandra и HBase, проверка "логин занят?") | несколько быстрых хешей | быстро и с малой памятью отвечает "точно нет" или "возможно есть" |
| 6. Консистентное хеширование (распределение ключей по серверам кеша, Memcached, DynamoDB) | MD5 / murmur по кругу | при добавлении сервера переезжает примерно 1/N ключей, а не почти все |
| Хеш-таблицы (dict в Python, HashMap в Java, индексы HASH в PostgreSQL) | быстрые некриптографические (SipHash, murmur, xxHash) | поиск, вставка и удаление в среднем за O(1) |
| Git | SHA-1 (переходит на SHA-256) | идентификатор коммита, дерева, файла: содержимое адресуется по хешу |
| Блокчейн | SHA-256 (Bitcoin), Keccak (Ethereum) | связь блоков в цепочку и доказательство работы |
| Цифровая подпись, HMAC, JWT | SHA-256 внутри HMAC или подписи | подписывается не весь документ, а его хеш; HMAC подтверждает, что сообщение не меняли |
| Кеширование и мемоизация, ETag в HTTP | любой хеш от аргументов или содержимого | ключ кеша; браузер не перекачивает файл, если ETag не изменился |
| Балансировщики нагрузки | хеш от IP клиента | один и тот же клиент всегда попадает на один сервер (sticky-сессии) |

Криптографические хеши (SHA-256) нужны там, где важна стойкость к подбору коллизий. Для таблиц и распределения данных берут быстрые некриптографические функции.
