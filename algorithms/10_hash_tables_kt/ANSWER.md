# КТ2-1. Хеширование

## Задание 1. Хорошие ли это хеш-функции (x это четырёхзначное число)

Хорошая хеш-функция детерминирована (один ключ всегда даёт один адрес), быстро считается, использует весь ключ и равномерно раскладывает ключи по адресам. Для проверки в `solution.py` все 9000 четырёхзначных чисел прогнаны через каждую функцию.

| Функция | Вывод | Почему |
|---|---|---|
| i) random(0, 3000) | плохая | не детерминирована: тот же ключ при поиске получит другой адрес, и записанный элемент не найдётся. Ещё и диапазон 0..3000 не совпадает с заявленным 0..1000 |
| ii) x mod 1301 | хорошая | детерминирована, считается за O(1), учитывает всё число. 1301 простое, поэтому остатки распределены равномерно: 1301 разных значений, в одной ячейке не больше 7 ключей (9000 / 1301 ≈ 6.9). Для таблицы размера 1301 подходит отлично |
| iii) len(x) | очень плохая | у всех четырёхзначных чисел длина 4, то есть все 9000 ключей в одной ячейке. Таблица вырождается в список, поиск O(n) |
| iv) сумма цифр | плохая | всего 36 значений (1..36), распределение "колоколом": суммам около 18 соответствует до 615 чисел, а краям по одному. Числа из одних и тех же цифр (1234, 4321, 2143) всегда сталкиваются |
| v) x0 + 5*x1 + 25*x2 + 125*x3 | средняя | детерминирована и учитывает все цифры и их позиции, получилось 1404 значения и до 8 ключей в ячейке. Но основание 5 меньше 10, поэтому разные числа дают одно значение: цифра 5 в разряде x1 даёт столько же, сколько цифра 1 в разряде x2 (например, 1500 и 1010 оба дают 26). Это не взаимно однозначное отображение. Для таблицы её всё равно придётся брать по модулю размера |

## Задание 3. Упорядоченная цепочка

Борисов прав частично. Пусть средняя длина цепочки α = n/m.

- Неуспешный поиск ускоряется. В неупорядоченной цепочке надо просмотреть её целиком (α сравнений). В упорядоченной можно остановиться, как только встретился ключ больше искомого, в среднем примерно на середине (около α/2).
- Успешный поиск не меняется: в среднем всё равно просматривается половина цепочки до найденного элемента.
- Вставка становится дороже. В неупорядоченную цепочку элемент можно добавить в начало за O(1), а в упорядоченной надо найти его место, это O(α). Если перед вставкой всё равно проверяется, нет ли такого ключа, разница пропадает, потому что проход по цепочке нужен в обоих случаях.
- Удаление почти не меняется: сначала поиск (успешный, без выигрыша), потом удаление из списка за O(1).

Асимптотика у всех операций остаётся Θ(1 + α). При хорошей хеш-функции и α = O(1) цепочки короткие, и выигрыш от упорядоченности маленький. Ощутимую пользу даёт не упорядоченный список, а сбалансированное дерево во вторичной структуре: тогда даже длинная цепочка ищется за O(log α). Так сделано в HashMap в Java 8: при длине цепочки больше 8 она превращается в красно-чёрное дерево.
