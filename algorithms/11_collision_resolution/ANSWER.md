# Другие способы разрешения коллизий

Кроме обычного метода цепочек (закрытая адресация) и линейного, квадратичного пробирования и двойного хеширования (открытая адресация), есть ещё несколько способов. Три из них реализованы в `solution.py` на одних и тех же ключах [20, 31, 42, 53, 7, 18, 29, 40, 13], таблица размера 11.

## 1. Кукушкино хеширование (cuckoo hashing)

Две таблицы и две хеш-функции. Ключ может лежать только в одном из двух мест: T1[h1(k)] или T2[h2(k)]. Если место занято, новый ключ вытесняет старый, а тот переезжает в своё место в другой таблице, и так далее, как кукушонок выталкивает птенцов из гнезда. Если вытеснения пошли по кругу (в примере это случилось на ключе 40), таблицу перестраивают с новым размером.

- Плюс: поиск и удаление всегда не больше 2 проверок, то есть O(1) в худшем случае.
- Минус: вставка иногда дорогая (цепочка вытеснений, перестроение), заполнение таблиц обычно держат меньше 50%.

## 2. Хеширование Робин Гуда (Robin Hood hashing)

Это линейное пробирование с одним правилом: при вставке сравниваем, как далеко каждый ключ от своего домашнего адреса. Если новый ключ ушёл дальше ("беднее"), чем тот, что лежит в ячейке, они меняются местами, и дальше ищет место уже "богатый". В итоге расстояния выравниваются, и длинных хвостов не бывает.

- Поиск отсутствующего ключа можно прекратить раньше: как только встретился ключ, который ближе к своему дому, чем мы ушли от своего.
- Удаление без маркеров DELETED: следующие элементы сдвигаются на шаг назад (backward shift).
- Используется в Rust (старая версия HashMap) и во многих быстрых C++ таблицах.

## 3. Связанное хеширование (coalesced hashing)

Смесь цепочек и открытой адресации. Элементы лежат в самом массиве, но у каждой ячейки есть поле next, как в списке. При коллизии элемент кладётся в свободную ячейку (сначала в "подвал", дополнительную зону в конце массива), и к ней тянется ссылка. Цепочки разных адресов могут сливаться (отсюда название).

- Плюс: нет отдельных узлов в куче, память компактная, поиск идёт только по своей цепочке.
- Минус: цепочки сливаются, удаление сложное.

## 4. Ещё способы (без кода)

- Хеширование "двух выборов" (2-choice). Две хеш-функции, ключ кладём в ту цепочку из двух, которая короче. Максимальная длина цепочки падает с O(log n / log log n) до O(log log n).
- Цепочки на деревьях. Вместо списка в бакете сбалансированное дерево. Так сделано в HashMap в Java 8: при длине цепочки больше 8 список превращается в красно-чёрное дерево, худший случай поиска O(log n).
- Hopscotch hashing. Каждый ключ обязан лежать не дальше H ячеек от дома, и для каждой ячейки хранится битовая карта "соседей". Поиск смотрит только H ячеек, это удобно для кеша процессора.
- Идеальное хеширование (perfect hashing). Для заранее известного набора ключей строится функция без коллизий: двухуровневая схема FKS или генераторы вроде gperf. Используется для ключевых слов в компиляторах.
- Расширяемое и линейное хеширование. Таблица растёт постепенно по одному бакету, без полного перестроения. Применяется в базах данных и файловых системах.
