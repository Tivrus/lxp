# КТ: алгоритм Дейкстры и его частные случаи

Код обеих задач в solution.py.

## Задержки в сети

Модель. Граф G: вершины это маршрутизаторы (r штук), рёбра это провода с весом w (длина в метрах, целое положительное). Задержка маршрутизатора это длина кратчайшего пути до ближайшей точки входа. Нужна сумма этих расстояний по всем маршрутизаторам.

Сведение к одному источнику. Добавим фиктивную вершину s и соединим её рёбрами веса 0 со всеми точками входа. Тогда задержка v = δ(s, v), а ответ это Σ δ(s, v). В коде это сделано так: все точки входа кладутся в начальную очередь с расстоянием 0 (многоисточниковый поиск).

Почему можно O(r), а не O((V + E) log V). Обычная Дейкстра с кучей даёт O(E log r). Но здесь две особенности:

1. Число проводов E <= 100r. Каждый провод длиной не меньше 1 метра, а общая длина сети не больше 100r, значит проводов не больше 100r = O(r).
2. Любое кратчайшее расстояние не больше общей длины сети L <= 100r. Расстояния это целые числа от 0 до L.

Поэтому вместо кучи берём массив "корзин" buckets[0..L] (алгоритм Дейкстры с корзинами, алгоритм Дайла): в корзине d лежат вершины с текущей оценкой расстояния d. Корзины просматриваются по возрастанию d. Вершина, вынутая из корзины d с dist = d, окончательна, потому что все веса положительны. Ребро релаксируется один раз при обработке своего конца: новая оценка кладётся в корзину d + w за O(1).

Время:
- проход по всем корзинам: O(L) = O(100r) = O(r);
- обработка вершин и рёбер: O(r + E) = O(r + 100r) = O(r);
- суммирование: O(r).

Итого O(r).

То же можно получить по-другому: разбить каждый провод длины w на w рёбер длины 1 (добавив w - 1 промежуточных вершин). Новый граф имеет не больше r + L вершин и L рёбер, то есть O(r), а кратчайшие пути в нём ищет обычный BFS из всех точек входа за O(r).

## Свадебное путешествие

Модель. Ориентированный граф: вершины это c городов, дуги это f прямых рейсов (откуда -> куда). Вес у всех рёбер одинаковый (один перелёт), значит кратчайший путь по числу перелётов ищет BFS за O(c + f).

Алгоритм:

1. Запускаем BFS четыре раза: из родного города H и из каждого туристического города T1, T2, T3. Каждый BFS хранит расстояния и массив предков parent для восстановления пути.
2. Из этих четырёх запусков известны кратчайшие расстояния между всеми нужными парами: H->Ti, Ti->Tj, Ti->H.
3. Порядков посещения всего 3! = 6. Для каждого порядка (Ta, Tb, Tc) считаем d(H, Ta) + d(Ta, Tb) + d(Tb, Tc) + d(Tc, H) и выбираем минимум. Если какое-то расстояние бесконечно, порядок не подходит.
4. Маршрут восстанавливаем, склеивая четыре кратчайших пути по массивам parent.

Почему это верно. Оптимальный маршрут состоит из четырёх отрезков между обязательными точками. Каждый отрезок можно заменить кратчайшим, и общее число перелётов не увеличится. Поэтому достаточно перебрать порядок городов и взять кратчайшие отрезки. Промежуточные пересадки могут проходить через любые города, в том числе через туристические, это не мешает.

Время: 4 * O(c + f) на BFS, плюс 6 вариантов по O(1), плюс восстановление маршрута O(c). Итого O(c + f).
